# LLRWD-RMS 前端品質審查報告
**審查日期：** 2026-03-25
**審查範圍：** Next.js 15 App Router + React 19 + Tiptap + Zustand 前端架構

---

## 執行摘要

LLRWD-RMS 前端整體品質優良，正確採用 Next.js App Router 的 Server Components 架構，Server Action 整合規範，Tiptap 擴充功能設計合理。發現 **0 個 Critical 問題、2 個 High 優先級問題、5 個 Medium 問題、3 個 Low 問題**。

**整體評級：** 4/5 — 生產就緒，建議修正 High 和 Medium 問題後部署。

---

## 1. React Server Components (RSC) 正確使用

### 優良實踐

1. **Page Components 正確為 RSC** — 所有頁面皆為 async RSC，資料 fetch 在 server 端執行
2. **'use client' 邊界合理** — Client Components 僅用於互動性：表單、Modal、Zustand store 消費者
3. **Layout 的 data fetching** — `/src/app/items/[id]/layout.tsx` 在 layout 層 fetch sidebar 資料

### 問題清單

#### [High] F-1: ThemeContext 未整合進 RootLayout，主題系統未啟用

**位置：** `src/app/layout.tsx`
**問題：**
- `ThemeContext` 已在 `src/contexts/ThemeContext.tsx` 中定義，但 RootLayout 未包含 `<ThemeProvider>`
- Navbar (`src/components/layout/Navbar.tsx` L38-45) 直接操作 `localStorage` 和 `document.documentElement.setAttribute`，繞過 Context
- 這導致主題狀態無法在其他元件中通過 `useTheme()` hook 存取，違反單一數據源原則

**修復建議：** 整合 `ThemeProvider` 進 RootLayout，Navbar 改用 `useTheme()` hook。

---

#### [High] F-2: Sidebar 在 item create/delete 後 revalidation 策略不明確

**位置：** `src/app/items/[id]/layout.tsx`, 各 Server Action
**問題：**
- Layout fetch 的 sidebar 資料在 Server Action 完成後不保證自動刷新
- 多數 Server Action 呼叫 `revalidatePath()` 但路徑不一致

**修復建議：** 統一使用 `revalidatePath('/items', 'layout')` 或建立 revalidation helper。

---

#### [Medium] F-3: Streaming/Suspense 使用不足

**位置：** `src/app/items/[id]/page.tsx` 等頁面
**問題：** 頁面中多個獨立 database queries 未使用 `<Suspense>` 分段串流，整個頁面阻塞直到所有資料 fetch 完成。

---

#### [Medium] F-5: Tiptap content 長度未在前端驗證

**位置：** `src/components/editor/RichTextEditor.tsx`
**問題：** 編輯器允許無限長度 HTML 內容，Server Action 中也未見明確的長度上限檢查。

---

#### [Medium] F-6: RichTextEditor XSS 風險極低但可加強防禦

**位置：** `src/components/editor/extensions/ItemLink.ts` L79
**問題：** `itemId` 由 API 取得為 number，風險極低，但建議加入 `Number.isInteger()` 防禦性檢查。

---

#### [Medium] F-7: Server Action 成功後 revalidate 路徑不一致

**位置：** 多個 Server Actions
**問題：** 部分用 `/items`，部分用 `/projects/${id}`，未統一使用 `revalidateTag()`。
**修復建議：** 建立統一 revalidation helper 函式。

---

#### [Medium] F-9: 部分表單使用 useActionState，部分使用手動 async/await

**問題：** 表單模式不完全一致。建議逐步統一遷移到 `useActionState`。

---

#### [Low] F-4: ItemLink 點擊時 href="#" 使用 alert() UX 不佳

**位置：** `src/components/editor/extensions/ItemLink.ts` L169-177
**修復建議：** 改用 tooltip 或 inline error badge。

---

#### [Low] F-8: DeleteItemButton 使用 alert() 而非 toast

**位置：** `src/components/item/DeleteItemButton.tsx` L63-66
**修復建議：** 統一改用 toast notification system。

---

#### [Low] F-10: Modal 元件未抽象成共用元件

**位置：** 多個元件重複實作 modal overlay
**修復建議：** 建立 `/src/components/ui/Modal.tsx` 共用元件。
