# LLRWD-RMS 安全審查報告

**審查日期**: 2026-03-25
**審查範圍**: 認證、授權、檔案上傳、備份還原、XSS/CSRF/SQL Injection

---

## 摘要

本次審查發現 **2 個 Critical**、**3 個 High**、**5 個 Medium**、**3 個 Low** 等級的安全問題。系統整體架構設計良好，但在部分邊緣案例存在授權繞過風險。

**安全評分: 78/100**

---

## 發現問題清單

### [Critical] S-1: item-relations.ts 缺乏認證檢查

**位置**: `src/actions/item-relations.ts` L38, L107, L127, L151
**問題**: `addRelatedItem`、`removeRelatedItem`、`updateRelatedItemDescription`、`getRelatedItems` 四個 server action 完全沒有呼叫 `getServerSession()` 進行認證檢查。任何未登入的使用者都可以呼叫這些函式來修改項目關聯。
**修復**: 加入 `getServerSession(authOptions)` 認證 + 角色檢查。

---

### [Critical] S-2: search.ts 缺乏認證檢查

**位置**: `src/actions/search.ts` L45
**問題**: `searchProjectItems` 函式沒有認證檢查，任何人（包括未登入使用者）都可以搜尋專案內容，可能洩漏敏感專案資訊。
**修復**: 加入 session 檢查。

---

### [High] S-3: datafiles/upload MIME type 回退邏輯問題

**位置**: `src/app/api/datafiles/upload/route.ts` L136
**問題**: 雖然 L99 正確拒絕空 `file.type`，但 L136 回應使用 fallback `file.type || 'application/octet-stream'`，未來修改驗證邏輯時可能成為漏洞。
**修復**: 移除 fallback，直接使用 `file.type`。

---

### [High] S-4: JWT Session 中的 isPM/isQC flag 可能過期

**位置**: `src/lib/auth.ts` L167-188
**問題**: `isPM` 和 `isQC` 資格存儲在 JWT payload 中，只在登入時設定一次。管理員撤銷某使用者資格後 JWT 仍包含舊 flag。`qc-approval.ts` 正確使用 `getUserQualifications()` 從 DB 驗證，但需確保所有涉及 QC/PM 的操作都使用此模式。
**修復**: 所有涉及 QC/PM 權限的操作都應呼叫 `getUserQualifications()` 從 DB 驗證。

---

### [High] S-5: getCategories() 缺乏認證檢查

**位置**: `src/actions/project-category.ts` L44
**問題**: 任何人都可以取得專案分區列表。
**修復**: 加入 session 檢查。

---

### [Medium] S-6: 帳號鎖定存在潛在 Race Condition

**位置**: `src/lib/auth.ts` L119-142
**問題**: 帳號鎖定計數使用「讀取 → 計算 → 更新」的非原子操作，攻擊者同時發送多個登入請求可能繞過 5 次嘗試限制。
**修復**: 使用 Prisma 的 `{ increment: 1 }` 原子操作。

---

### [Medium] S-7: 備份檔案包含密碼雜湊

**位置**: `src/lib/backup-utils.ts` L40-56
**問題**: 資料庫備份匯出整個 User 資料表，包含 bcrypt 雜湊的密碼。
**修復**: 匯出時排除或遮罩密碼欄位。

---

### [Medium] S-8: uploads/[...path] route 的 SVG 處理

**位置**: `src/app/uploads/[...path]/route.ts` L33
**問題**: MIME_TYPES 包含 SVG，某些瀏覽器配置下仍可能執行。
**修復**: 移除 SVG 支援或加入 Content-Security-Policy header。

---

### [Medium] S-9: Middleware matcher 的潛在繞過

**位置**: `src/middleware.ts` L49
**問題**: 排除 pattern 如 `api/upload` 會匹配所有子路徑，未來新增路由可能忘記加入認證。
**修復**: 使用更精確的 pattern。

---

### [Medium] S-10: LoginLog 無清理機制

**位置**: `src/lib/auth.ts` L81-96
**問題**: 登入日誌無限累積，可能導致資料庫膨脹。
**修復**: 實作定期清理機制，保留最近 90 天。

---

### [Low] S-11: Error 訊息可能洩漏實作細節

**位置**: 多個 server actions
**問題**: 部分 action 回傳 `e.message`，可能洩漏內部資訊。

### [Low] S-12: getProjects() 無認證檢查

**位置**: `src/actions/project.ts` L143

### [Low] S-13: NextAuth cookie 設定未明確指定

**位置**: `src/lib/auth.ts`
**問題**: 依賴 NextAuth 預設值，應明確指定 httpOnly、secure、sameSite。

---

## 正面發現

1. **自我審批防護**: `approval.ts` L885 和 `data-files.ts` L363 正確實作
2. **Zip Slip 防護**: 所有 restore route 都有路徑穿越檢查
3. **Open Redirect 防護**: 使用 `/^\/[^/]/` regex 正確防護
4. **XSS 防護**: 使用 `isomorphic-dompurify` sanitize
5. **SQL Injection 防護**: Prisma ORM + SQL 白名單驗證
6. **MIME Type 白名單**: 已移除 `application/octet-stream`
7. **檔名 UUID 替換**: 使用 `crypto.randomUUID()`
8. **Path Traversal 防護**: `path.basename()` + `path.resolve()` 雙重驗證
